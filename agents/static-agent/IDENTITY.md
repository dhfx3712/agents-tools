# IDENTITY.md（北极星指标OpenClaw数据分析项目）
## 1. 项目基本信息
- 项目名称：北极星指标OpenClaw数据分析项目（简称：指标分析项目）
- 版本号：V1.0
- 创建时间：2026-04-22
- 维护团队：数据分析组（负责人：张三，联系方式：zhangsan@xxx.com）、运维组（负责人：李四，联系方式：lisi@xxx.com）
- 核心用途：基于OpenClaw工具，实现北极星指标（GMV、订单量）的异动识别、维度拆解、归因分析、趋势分析及经营报告生成，通过SQL模板固化指标口径、维度映射、表关联，保障数据取数准确、口径统一、结果可复现，替代传统手动SQL、Excel分析模式。
- 适配环境：MySQL 8.0、OpenClaw V2.0+、Excel 2019+、DataX（数据导入工具）

## 2. 核心定位与业务价值
### 2.1 核心定位
面向业务经营分析，提供“数据标准化→SQL模板固化→OpenClaw交互分析→报告生成”的全流程解决方案，聚焦北极星指标全生命周期分析，实现业务与技术的高效协同，降低业务人员使用门槛，提升数据分析效率与数据可信度。

### 2.2 业务价值
1.  解决核心痛点：杜绝数据分析中“口径不统一、取数效率低、结果不可复现、异动归因不精准”的问题，避免人工操作失误导致的数据偏差。
2.  提升分析效率：业务人员无需编写SQL，通过自然语言指令即可快速获取分析结果，缩短分析周期（从小时级缩短至分钟级）。
3.  支撑经营决策：为日常指标监控、异动排查、月度/季度经营复盘、数据汇报提供可信、标准化的数据支撑，助力业务优化。

### 2.3 差异化优势
1.  口径固化：通过SQL模板、语义层配置，将指标口径、维度映射、表关联完全固化，杜绝黑盒取数，确保所有分析口径统一。
2.  流程管控：强制SQL人工复核机制，所有取数操作均需审核，保障数据准确性，可追溯、可审计。
3.  易用性强：适配OpenClaw自然语言交互，业务人员无需掌握SQL、数据库知识，即可完成核心分析需求。

## 3. 项目边界与范围
### 3.1 核心功能范围
1.  数据接入：Excel数据标准化处理、通过DataX导入MySQL数据库，数据校验（完整性、规范性）。
2.  系统配置：OpenClaw环境配置（.env文件）、语义层配置（semantic_polaris.yaml）、SQL模板维护。
3.  分析功能：北极星指标（GMV、订单量）异动识别（环比±10%阈值）、维度拆解（渠道、省份）、归因分析、近7/30天趋势分析。
4.  报告生成：基于SQL执行结果，自动生成标准化经营分析报告，支持Excel、PDF导出。

### 3.2 不涉及范围
1.  不开发新的数据库系统，仅基于现有MySQL数据库进行适配。
2.  不新增OpenClaw核心功能，仅对其进行配置适配（语义层、SQL模板）。
3.  不涉及非北极星指标的深度分析（如用户行为细查、产品品类明细分析）。
4.  不支持海量数据实时分析（仅支持日度数据批量分析）、非结构化数据（文本、图片）分析。

### 3.3 适用与不适用场景
- 适用场景：日常指标监控、异动排查、月度/季度经营复盘、数据汇报、业务决策支撑。
- 不适用场景：实时数据监控、海量数据（千万级以上）分析、非结构化数据处理、定制化SQL开发（超出模板范围）。

## 4. 项目统一规范
### 4.1 术语定义（统一表述，禁止歧义）
1.  北极星指标：本项目核心指标，特指GMV（口径：付款金额-退款金额，已剔除取消订单）、订单量（口径：实际支付成功的订单数量，剔除取消、退款订单）。
2.  语义层：OpenClaw的核心配置层，用于绑定指标口径、维度映射、表关联，实现指令与SQL模板的联动。
3.  SQL模板固化：将指标计算逻辑、维度映射规则、表关联逻辑写死到SQL模板，仅保留时间、维度等动态参数，确保口径统一。
4.  异动：指标环比波动超过±10%，视为异动，需进行归因分析。
5.  维度拆解：将北极星指标按渠道（电商、门店、分销）、省份（广东、浙江、江苏）进行拆分，分析各维度的贡献度。

### 4.2 命名规范（严格遵循，避免混乱）
1.  数据库表名：事实表前缀“fact_”，维度表前缀“dim_”，如fact_polaris_daily（北极星指标日度事实表）、dim_channel（渠道维度表）。
2.  SQL模板命名：格式“场景_模板类型.sql”，如gmv_abnormal.sql（GMV异动分析模板）、gmv_dimension.sql（GMV维度拆解模板）。
3.  配置文件命名：固定为.env（OpenClaw环境配置）、semantic_polaris.yaml（语义层配置），不允许修改文件名。
4.  文档命名：固定为IDENTITY.md、user.md、AGENTS.md，版本更新后标注版本号（如IDENTITY_V1.1.md）。

### 4.3 口径规范（所有分析均需遵循）
1.  GMV：SUM(gmv)，口径为付款金额-退款金额，已在事实表中计算完成，模板直接调用sum聚合。
2.  订单量：SUM(order_cnt)，口径为实际支付成功的订单数量，剔除取消、退款订单。
3.  客单价：ROUND(IF(SUM(order_cnt)=0, 0, SUM(gmv)/SUM(order_cnt)), 2)，处理订单量为0的异常场景。
4.  时间格式：统一为“YYYY-MM-DD”，如2026-04-22，禁止使用其他格式。
